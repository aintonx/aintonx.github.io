# EchoWorld — правила работы с сайтом

Одностраничный сайт echoworld.space. Весь сайт — один файл `index.html`:
~39 800 строк, 44 блока стилей, 47 инлайновых скриптов, без сборки.
Из-за этого любая правка вносится вслепую, и без проверок ошибки уходят в
деплой незамеченными.

## Обязательные гейты

Ни одна правка не считается сделанной, пока не прошли обе команды:

```bash
npm run check     # целостность + stylelint
npm run shots:diff   # визуальная регрессия по эталонам
```

`npm run check` = `tools/validate.mjs` + stylelint. Валидатор ловит то, что
не ловит ничто другое: **правило, проглоченное незакрытым комментарием** —
такая поломка не даёт синтаксической ошибки, файл выглядит целым, а стили
молча не применяются. Плюс баланс скобок, синтаксис скриптов, повторяющиеся
id (на них держится вся машинерия), парность тегов.

Валидатор висит хуком на каждой правке — см. `.claude/settings.json`.

## Визуальная проверка

**Панель предпросмотра редактора не перерисовывает содержимое ниже первого
экрана** — середину сайта в ней проверять нельзя, кадры приходят чёрными.
Для этого есть стенд:

```bash
npm run shots            # снять текущее состояние всех зон
npm run shots:diff       # сравнить с эталонами, карты различий в tools/shots/diff
npm run shots:baseline   # обновить эталоны — только когда блок принят
node tools/shots.mjs --zone catalog --size mobile   # одна зона
```

Зоны и способ до них добраться — `tools/zones.mjs`, порядок = путь покупателя.

### Движок Safari и обязательный контроль

```bash
node tools/webkit.mjs                          # пробы в WebKit и в Chromium
PAGE=/tmp/старый.html node tools/webkit.mjs    # контроль против другой версии
```

Часть дефектов живёт только в Safari, и Chromium по ним показывает честный
ноль. Но **headless WebKit из Playwright — не то же, что Safari на iPhone.**
Проверено: контрольный прогон заведомо сломанной версии дал ноль расхождений
по обоим дефектам, которые владелец видел на телефоне (крестик в чек-боксе и
осциллограф). **Зелёный результат здесь ничего не доказывает.**

Отсюда правило: **проба сначала запускается на СТАРОЙ версии.**

```bash
git show HEAD:index.html > /tmp/старый.html
```

Не воспроизвёлся дефект там — значит проба его не ловит, и слово «починил»
не заслужено. (Имя переменной латиницей: zsh не принимает кириллицу в
именах переменных окружения и падает до запуска node.)

Когда воспроизвести не удаётся — не гадать о причине, а убирать конструкции,
чьё поведение зависит от движка: проценты и `transform` внутри SVG, лишние
пересчёты координат через `<use>` на `<symbol>`, покадровую правку атрибутов
у узлов под `filter`. И отдавать сборку на телефон через `serve.mjs` ДО
деплоя, а не после.

### Оседание раскладки при загрузке

```bash
npm run settle                              # что переезжает, пока страница грузится
SIZE=desktop npm run settle
PAGE=/tmp/старый.html node tools/settle.mjs # контроль против старой версии
```

Сайт — один файл в 1.9 МБ. **Правило, лежащее в конце файла, применяется уже
после первой отрисовки** — браузер рисует первый экран, не дождавшись хвоста
документа. Владелец видит это как «текст прыгает при загрузке». Обычный стенд
такое не ловит: он снимает кадр, когда всё осело.

Отсюда правило: **новое значение правится в ИСХОДНОМ правиле, а не дописывается
блоком в конец файла.** Дописанный в конец блок победит по каскаду — но с
опозданием на всю загрузку, и это видно глазом. Если правило обязано быть
последним (спорит с группой на `!important`), его геометрию надо продублировать
ранней копией с теми же значениями: обе копии говорят одно и то же, и в какой
бы момент парсер ни оказался — раскладка стоит окончательная.

Так были найдены и починены: трекинг заголовка героя (−0.012em → 0.005em с
опозданием 750 мс), перевод шапки из `sticky` в `fixed` на 80% файла (весь
первый экран уезжал на 14px), перевёрстка лида на строку при подмене шрифта.

### Стенд снимает эталоны БЕЗ веб-шрифтов

`изолировать()` в `tools/stub.mjs` глушит все внешние запросы, включая Google
Fonts. `document.fonts.size` внутри стенда — 2 (только локальные подмены).
Значит **эталоны сняты запасным шрифтом, а не Oswald/Overpass/Plex.** Любая
правка запасных шрифтов двигает все кадры стенда, ничего не меняя на живом
сайте. Проверять такие правки надо отдельной пробой с `document.fonts.ready`,
а не по `shots:diff`.

### Ревизор языка «Линза»

```bash
npm run lens            # отчёт по нарушениям паспорта
npm run lens -- --strict   # ненулевой код выхода, если есть «важно»
```

Проверяет ВЫЧИСЛЕННЫЕ стили в браузере, а не текст CSS. Первая версия читала
исходник и утонула в ложных срабатываниях: в файле десятки слоёв-перекрытий,
и правило может быть трижды перекрыто ниже — статический разбор видит правило,
но не видит, что победило в каскаде. **Ревизор, который врёт, хуже
отсутствующего.**

Четыре проверки, каждая выросла из реальной поломки:
красный на действии · бесконечная анимация · дорогое свойство в переходе на
стекле · минусовой трекинг на заголовке.

Осознанные исключения живут в `ИСКЛЮЧЕНИЯХ` внутри `tools/lens.mjs`, **у
каждого обязательна причина**. Пропало основание — строку убрать.

### Поведение форм при клавиатуре

```bash
npm run thrash              # сколько раз форма заставляет пересчитать раскладку
node tools/serve.mjs 4199   # отдать сайт в локальную сеть — открыть с телефона
```

**Симулятор iOS на этой машине не работает — не предлагать.** MacBook Pro 2018 на
Intel: свежие рантаймы Apple оптимизирует под Apple Silicon, миграция данных
падает по таймауту, Safari открывается в чёрный экран, машину кладут 250
процессов. Проверять `uname -m` ДО многогигабайтных загрузок.

Вместо симулятора: `serve.mjs` слушает `0.0.0.0`, телефон в той же сети
открывает `http://<IP-мака>:4199/?debug=1` и видит НЕзадеплоенные правки —
проверять можно до выкладки, а не после.

`thrash` считает записи в раскладку (`overflow`, `scrollTop`, `window.scrollTo`)
за цикл «тап в поле → автоподстановка → уход фокуса». Это способ спорить
числами, а не словом «дёргается». Норма — **ноль**: всё, что пишется в этом
окне, попадает в анимацию iOS-клавиатуры и видно как рывок.

Историческая причина рывков была не в недостающей правке, а в **семи**
компенсаторах, добавленных за много итераций друг поверх друга. Сведены к
одному владельцу — `window.__ewKbdOwned()`; пока он истинен, остальные молчат.
**Не добавляй восьмой компенсатор** — сначала прогони `npm run thrash`.

## Что легко сломать

- **Dev-сервер редактора кеширует.** Ходить только с `?v=<число>`, иначе
  сверяешь замеры со старой сборкой. Стенд поднимает свой сервер без кеша.
- **Войны `!important`.** В файле есть правила-«унификаторы» на десятки
  селекторов сразу. Прежде чем чинить элемент точечно, проверь, не держит ли
  его такое правило: точечная правка молча проиграет.
- **Светлая тема выведена из эксплуатации**, но её CSS ещё лежит в файле
  (255 селекторов). Оба бутстрапа держат `light = false`, `applyTheme` форсит
  `dark`. Правила `:root[data-theme="light"]` мёртвые. **Осторожно:**
  `:root:not([data-theme="light"])` — наоборот, живое правило тёмной темы.

## Границы

- **Деплой делает только владелец.** Не коммитить и не пушить без явной
  просьбы. Деплой — `.github/workflows/pages.yml`, белый список файлов;
  `.claude/`, `tools/`, `design/`, `node_modules/` в сборку не попадают.
- **`~/Desktop/BACKUP/index.html` не трогать** — эталонная копия только для
  чтения.
- **`design/` не деплоится** — там согласованные референсы:
  `modals-glass.html` (окна) и `site-v2.html` (секции). Это спецификация
  визуала, а не черновики.
- Значения ЮKassa, SmartCaptcha и dadata не менять.

## Язык «Линза»

Паспорт — в скилле `.claude/skills/lens/SKILL.md`. Коротко: пять осей —
форма, материал, типографика, цвет-роль, ритм. Самое частое нарушение —
**красный не по делу**: красный означает только тревогу и запрет, главное
действие тёплое, выбранное и подтверждённое — циановое.
