# Записи в базу: что сделано и что нужно сделать вам

Документ для человека, который не работал с базами данных. Читается сверху вниз,
шаги выполняются по порядку. Ничего из перечисленного не связано с деньгами:
платежи остаются выключенными, пока не появятся ключи ЮKassa.

---

## Коротко: как всё устроено

Три части, между которыми ходят данные:

1. **Сайт** — `index.html` на GitHub Pages. Собирает то, что заполнил человек.
2. **Облачная функция** — `api/echoworld-apertura-api/index.js` в Яндекс Облаке.
   Принимает данные от сайта, проверяет их и кладёт в базу. Это единственное
   место, которое имеет право писать в базу; сайт напрямую в неё не ходит.
3. **База YDB** — таблицы в Яндекс Облаке. Здесь данные лежат.

Сайт → функция → база. Если хоть одно звено не готово, запись не доходит.

## Что было не так

**Сайт не записывал в базу ничего.** Ни заказов, ни заявок. Человек заполнял
форму, видел «заявка принята» — и на этом всё заканчивалось, данные никуда не
уходили.

Причин было три, все найдены проверкой, а не на глаз:

1. Главный рубильник записей `businessApi` стоял в положении «выключено», и
   режим работы сайта был `preview` — «показываем, но не пишем».
2. У всех пятнадцати маршрутов записи **не был указан адрес бэкенда**. Запрос
   собирался как `/condensation/create` — то есть уходил бы на сам сайт, где
   такого адреса нет. Этот дефект был тихим: пока рубильник выключен, до сборки
   адреса дело не доходило, и заметить его можно было только включив запись.
3. Для заявок на конденсацию и возврат **не существовало ни таблиц в базе, ни
   обработчиков в функции** — данные было некуда класть.

## Что я уже сделал в коде

- Создал файл со схемами двух таблиц: `api/echoworld-apertura-api/schema/requests.yql`
- Написал в функции два обработчика: `condensation/create` и `return/create`
- Проставил адрес бэкенда всем пятнадцати маршрутам записи
- Включил режим `production` и флаги двух безопасных маршрутов
- **Привязал экран успеха к ответу сервера.** Раньше «заявка принята»
  показывалось всегда; теперь — только если сервер подтвердил запись. Если
  запись не прошла, человек видит окно ошибки и может отправить заново
- Сделал стенд проверки: `npm run dbcheck`

Платёжные маршруты остались выключенными, и это проверяется стендом отдельно.

## Шаг 1. Найти свою базу

1. Откройте [console.yandex.cloud](https://console.yandex.cloud) и войдите.
2. Слева выберите **каталог** (папку) вашего проекта — обычно он один.
3. В списке сервисов найдите **Managed Service for YDB**.
4. Откройте вашу базу. Если баз несколько — нужна та, чьё имя совпадает с
   переменной `DATABASE` в настройках функции (где её посмотреть — шаг 3).

Если базы нет вовсе — остановитесь и скажите мне, дам отдельную инструкцию на
создание с нуля.

Официальная страница на случай, если названия в консоли отличаются:
<https://yandex.cloud/ru/docs/ydb/quickstart>

## Шаг 2. Создать две таблицы

1. Внутри базы найдите раздел для выполнения запросов — он называется
   **«Обзор» → «SQL-запрос»** или просто **«Запросы»** (в разных версиях
   консоли по-разному, ищите поле, куда можно вписать текст запроса).
2. Откройте файл `api/echoworld-apertura-api/schema/requests.yql` из репозитория.
3. Скопируйте **весь** его текст и вставьте в поле запроса.
4. Нажмите **«Выполнить»**.

Как понять, что получилось: в разделе с деревом таблиц появятся
**condensation_requests** и **return_requests**.

Если увидите ошибку со словами `path exists` — значит таблица с таким именем уже
есть. Это не поломка, просто повторный запуск. Ничего страшного не произошло.

## Шаг 3. Обновить облачную функцию

Функция — это код, который вы уже выкладывали раньше; сейчас в нём появились два
новых обработчика.

1. В консоли откройте **Cloud Functions** → вашу функцию (её идентификатор
   `d4e5vcvae4csacbacs2i`, он же виден в адресе, который вызывает сайт).
2. Откройте вкладку **«Редактор»**.
3. Загрузите обновлённый `api/echoworld-apertura-api/index.js` тем же способом,
   которым выкладывали раньше — через ZIP-архив или напрямую в редакторе.
4. Проверьте, что в блоке **«Переменные окружения»** остались прежние значения:
   `ENDPOINT`, `DATABASE`, `SMARTCAPTCHA_SERVER_KEY`. **Ничего не меняйте** —
   новые переменные для этих двух заявок не нужны.
5. Нажмите **«Создать версию»**.

Важное про права: функция пишет в базу от **сервисного аккаунта**, который
указан в её настройках. У него должна быть роль `ydb.editor` — только на чтение
(`ydb.viewer`) записи не пройдут. Если заявки будут доходить до функции, но не
появляться в таблице, причина почти наверняка здесь.

Официальная страница: <https://yandex.cloud/ru/docs/functions/operations/function/version-manage>

## Шаг 4. Выложить сайт

Обновлённый `index.html` нужно опубликовать обычным для вас способом
(commit + push, GitHub Pages подхватит сам). Коммит и публикацию делаете вы —
я в репозиторий ничего не отправляю.

## Шаг 5. Проверить, что записи доходят

### Проверка без риска, прямо сейчас

```bash
npm run dbcheck
```

Стенд поднимает копию сайта, подменяет собой облачную функцию и прогоняет обе
формы по-настоящему. Боевая база при этом не затрагивается вообще. Он проверяет:

- режим и флаги: заявки открыты, платежи закрыты;
- что прямой вызов оплаты отклоняется;
- что заполненная форма действительно уходит на сервер;
- что уходят именно те поля, которые человек ввёл;
- что при отказе сервера показывается ошибка, а не ложный успех.

Последняя строка должна быть **ВСЁ СОШЛОСЬ**.

### Проверка на живом сайте, после шагов 1–4

1. Откройте сайт, раздел **«Заказать конденсацию»**.
2. Заполните: предмет, почту, поставьте галочку согласия. Напишите что-нибудь
   узнаваемое, например `ПРОВЕРКА 9 августа`.
3. Отправьте.
4. Вернитесь в консоль Яндекс Облака, в вашу базу, и выполните запрос:

```sql
SELECT * FROM condensation_requests ORDER BY created_at DESC LIMIT 10;
```

Ваша заявка должна быть первой строкой. Посмотрите на поля: `item` — то, что вы
написали, `email` — ваша почта, `consent` — `true`, `status` — `new`.

То же самое для возврата — форма открывается из подвала сайта, ссылка
**«Возврат реликвии»**:

```sql
SELECT * FROM return_requests ORDER BY created_at DESC LIMIT 10;
```

### Если заявка не появилась

Смотрите по порядку, это отсекает половину вариантов на каждом шаге:

1. **Логи функции.** Консоль → Cloud Functions → ваша функция → вкладка
   **«Логи»**. Если запроса там нет — сайт до функции не достучался: проверьте,
   что выложили новый `index.html`.
2. **Ошибка в логах.** Если видите `ECHOWORLD_API_ERROR` со словами про таблицу —
   таблицы не создались, вернитесь к шагу 2.
3. **Ошибка про права.** Слова `permission denied` или `access denied` — у
   сервисного аккаунта нет роли `ydb.editor`, см. шаг 3.
4. **Ответ 400.** Функция получила заявку, но отказалась её писать. Коды:
   `consent_required` — не было галочки согласия;
   `invalid_email` — почта не похожа на почту;
   `missing_fields` — не заполнено обязательное поле.

## Что осталось выключенным и почему

| Что | Почему не включено |
|---|---|
| Покупка реликвии, резерв, оплата | Нужны ключи ЮKassa. Без них платёж не создать |
| Эхо (текст и голос) | Эхо платное: в его цепочке стоит тот же платёжный маршрут |
| Голосовое Эхо, загрузка записи | Дополнительно нужно хранилище Object Storage и ключи доступа к нему |
| Подписка на каталог | На сайте нет формы: кнопка есть, а полей для ввода нет. Это отдельная небольшая работа |
| Помощь Архитектора | То же самое — маршрут описан, формы нет |

Все они физически заблокированы: у каждого маршрута свой флаг, и попытка вызвать
его напрямую отклоняется с кодом `ROUTE_DISABLED`. Стенд это проверяет каждым
прогоном.

## Что писать в базу дальше

Когда появятся ключи ЮKassa, включается покупка. Для неё таблицы **уже есть**:
`products`, `product_reservations`, `product_reservation_locks`, `product_orders`,
`product_order_items`, `customers` — и обработчики в функции тоже написаны.
Останется дописать три недостающих (`payments/status`, `payments/retry`,
`reservations/status`) и включить флаги.

Для Эха таблицы ещё нет — её нужно будет создать вместе с включением оплаты.
